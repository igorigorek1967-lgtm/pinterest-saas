# Серверная версия исследования Pinterest

Текущая версия дополняет первоначальный `/research` постоянным хранилищем SQLite, входом владельца и четырьмя операциями Pinmetrica MCP непосредственно из интерфейса. Первоначальное описание в IMPLEMENTATION.md относится к v1; сведения о браузерном хранилище там исторические.

## Работа владельца

1. Войти в `/research` с паролем владельца.
2. Выбрать проект, режим (поиск / подсказки / категории / сведения о теме), язык записи и при необходимости страницу поиска 1–5.
3. Посмотреть ответ источника. Для ГЕО Ейска нерелевантные подстрочные совпадения помещаются отдельно. Поиск без подходящих результатов не означает отсутствия спроса.
4. Сохранить подходящие наблюдения. Для смежных тем предусмотрен ручной импорт с отдельным подтверждением.
5. Подготовить задание на основе сохранённого наблюдения. Задание сохраняется в SQLite и не дублируется при повторном нажатии.
6. Скачать задания для передачи в OmniHub. Автоматический транспорт не подключён: без подтверждённого контракта приёма модуль сохраняет `NOT_SENT` и не объявляет доставку.

Наблюдения, задания и сведения о прокси сохраняются между перезапусками и доступны с другого устройства при входе на тот же сервер. Старые данные localStorage не перезаписываются: есть явный перенос через импорт. Язык выбирает владелец; страна и дата обновления базы не выдумываются.

## Переменные окружения сервера

| Переменная | Значение |
|---|---|
| `RESEARCH_OWNER_PASSWORD_HASH` | Хеш scrypt, вывод create-owner.mjs |
| `RESEARCH_SESSION_SECRET` | Случайный секрет не короче 32 символов |
| `RESEARCH_PUBLIC_ORIGIN` | Точный внешний origin, например `https://research.example.com`, без завершающего `/` |
| `RESEARCH_DATA_DIR` | Абсолютная директория SQLite на постоянном томе |
| `PINMETRICA_API_KEY` | Ключ `pm_…`, только в защищённом окружении |
| `RESEARCH_SECURE_COOKIES` | По умолчанию Secure; `false` допустим только для локальной HTTP-проверки |

Вход не работает при отсутствии хеша или секрета. В production изменяющие запросы не работают без `RESEARCH_PUBLIC_ORIGIN`. Пароль не хранится в открытом виде. Сессия — подписанная HttpOnly/SameSite=Strict cookie на 12 часов с серверной записью хеша токена в SQLite. Выход отзывает запись; изменение хеша пароля делает старые сессии недействительными. POST-запросы проверяют origin и JSON. Счётчик неправильных паролей сохраняется в SQLite и после 10 попыток возвращает 429 неправильному паролю, но не блокирует правильный. Это не защита от перебора: каждый кандидат всё равно проверяется. Размещение запрещено до фактической проверки ограничения частоты на ingress либо закрытия ingress через VPN/allowlist. Приложение нельзя открывать напрямую в обход этой защиты.

Скрипт `scripts/research/create-owner.mjs` принимает новый пароль только через стандартный ввод и возвращает хеш и случайный секрет для защищённого окружения. Не сохранять результат в git или журналах. Ключ MCP не отправляется в браузер; прямые запросы всегда идут на фиксированный HTTPS-адрес без перенаправлений.

## Размещение

Подготовлен Dockerfile с Node 24.19.0 и standalone Next.js. Процесс работает от uid/gid 1001, порт 3000. `/app/var/research` должен находиться на постоянном томе с правом записи uid 1001. HTTPS завершается на существующем обратном прокси. Для первого размещения использовать отдельное приложение на выбранном владельцем OnDash; действующие приложения не заменять.

До рабочего запуска требуются независимое ревью, проверка постоянного тома и фактическая проверка входа с другого устройства. Для резервной копии SQLite использовать online backup SQLite или остановленную согласованную копию вместе с WAL; обычное копирование одного работающего файла не гарантирует согласованность. В интерфейсе есть полный резервный JSON v2: все наблюдения, индексы заданий и сведения о прокси. Восстановление — отдельная операция до 20 000 наблюдений / 200 МБ, атомарно объединяет данные без удаления существующих; конфликты отклоняют всю операцию. Задания пересоздаются по сохранённым наблюдениям с OWNER_REVIEW / NOT_SENT. Сведения о прокси заменяются значениями из копии. Пароли, ключи, сессии и история неудачных входов в JSON не включаются. Старый v1 JSON содержит только наблюдения и proxy; наблюдения можно перенести обычным импортом по 5000 записей / 2 МБ. Полным backup он не является. Для JSON v2 на reverse proxy нужен соответствующий лимит тела и ресурсы для обработки до 200 МБ.

## REA без зависимости от Mac

В `.github/workflows/research-checks.yml` добавлена отдельная проверка на обычном Linux. Она получает четыре уже наблюдавшихся публичных клиентских файла, запускает REA 6.7.0 и сохраняет результат на 7 дней. Пользовательские ключи, прокси и данные аккаунта в эту проверку не передаются. Полнота анализа ограничена выбранными файлами; серверная часть Pinmetrica остаётся недоступной.

Само наличие workflow ещё не доказывает успешный анализ. Окончательный статус берётся из фактического запуска GitHub Actions и его evidence.

## Проверка контейнера

В GitHub Actions добавлен отдельный job `container`: сборка Dockerfile и HTTP-проверка запуска, входа, origin, импорта, заданий, полной копии и восстановления. Контейнер пересоздаётся с тем же именованным томом; проверяются сохранность данных и сессии, затем отзыв cookie после logout. Вторая пустая БД проверяет восстановление. Используются только случайные одноразовые credentials и фикстуры, порт привязан к loopback; реальный MCP не вызывается. Это не проверяет внешний ingress, TLS и диск OnDash.
