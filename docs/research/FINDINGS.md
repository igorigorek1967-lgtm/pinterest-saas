# Выводы исследования

Живой каталог MCP содержит только четыре операции исследования ключей: search_keywords, suggest_keywords, get_categories, get_theme. Возможности веб-интерфейса шире; доступ к запуску сборщика через MCP не подтверждён.

Клиентский модуль сборщика выбирает активные прокси и блокирует форму без них. Оплаченный срок нужно брать у поставщика, а доступность соединения проверять отдельно. Чтение накопленных ключей через MCP не требует параметров прокси, но независимость закрытого сервера и обновления его базы от прокси не установлена.

В поиске «Ейск» встречаются «Корейский…» и «Европейский…». Поэтому собственная проверка релевантности обязательна. Отсутствие подходящих результатов на одной странице не означает отсутствия спроса.

MCP возвращает исследовательские результаты текстом с ключами, объёмами и ID тем. Наш адаптер переводит известный формат поиска в записи и останавливает импорт при неизвестном формате. Исходный текст доступен владельцу для проверки.

Интерфейс, вход владельца, SQLite, импорт, группировка и задания написаны заново. Клиентский код Pinmetrica, её закрытая база и ключи аккаунта в репозиторий не переносились. Источник MCP остаётся внешним: собственный модуль пока зависит от данных Pinmetrica.

Улучшения для наших задач: разделение проектов, доказательства для каждого наблюдения, защита от ложных географических совпадений и дублей, постоянные задания на проверку владельцу. Метрика, дата наблюдения, страна и источник сохраняются раздельно.

REA разобрал три выбранных прикладных файла на обычном Linux и сохранил evidence. Общий клиентский bootstrap исчерпал память анализатора. Контрольные суммы и границы — в VALIDATION.md. Закрытая серверная реализация не установлена. Для независимости от Pinmetrica нужны отдельно проверенные источники Pinterest и условия их использования; REA сам не создаёт базу спроса и историю.
