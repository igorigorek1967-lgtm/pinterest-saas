# Pinterest Research Workbench — первая версия

Ветка добавляет `/research` в существующий Next.js-проект. Код написан самостоятельно по наблюдаемому поведению. Клиентский код Пинметрики, выгрузки аккаунта, ключи и сетевые сессии в репозиторий не включены.

## Что работает

- Импорт CSV/JSON до 2 МБ и 5000 строк. Поля: `keyword`, `value`, `trendPercent`, `topicId` (необязательно). Для CSV поддержаны названия `Ключ`, `Объём`, `Тенденция`, разделители `,` и `;`, экранированные кавычки.
- Проект, язык, страна, тип показателя, источник и дата наблюдения сохраняются вместе с числом. Отсутствие данных не заменяется нулём. Индекс 0–100 не становится числом поисков.
- Повторы одного наблюдения пропускаются. Одинаковое слово с разными ID темы или странами сохраняется отдельно. Конфликт значений требует уточнения.
- Проверка «Ейск» как отдельного слова, включая формы «в Ейске», «ейская». «Корейский» не считается географическим совпадением. Смежные темы в ручном импорте требуют отдельного подтверждения.
- Группировка по намерению запроса по явным правилам. Это наше правило, а не подтверждённая классификация Pinterest.
- JSON-задание на статью и Pinterest-визуал с доказательствами и ключом идемпотентности. `delivery=NOT_SENT`; фактического транспорта OmniHub пока нет. Изображения и статьи этим модулем не генерируются.
- Метаданные прокси вносятся вручную: статус последней проверки, дата проверки UTC и срок. Свежесть — 24 часа; предупреждение — за три дня. Пароли не принимаются.
- Клиент MCP для сервера/CLI: инициализация, каталог и четыре наблюдавшихся инструмента чтения. Фиксированный HTTPS-адрес, запрет перенаправлений, таймаут и ограничение ответа. Ключ читается из окружения и не передаётся в браузер.

## Запуск

Node.js 24.19+ (для запуска TypeScript из тестов и CLI); npm.

```bash
npm ci
node --test --experimental-strip-types tests/*.test.mjs
npm run build
npm run start -- --hostname 127.0.0.1 --port 3035
```

Рабочая область: `http://127.0.0.1:3035/research`.

Хранилище интерфейса — localStorage текущего браузера. Оно не синхронизируется между телефоном и компьютером. Экспорт наблюдений содержит резервную копию; задания отдельно скачиваются до закрытия сессии. Публично этот прототип не развёрнут. Для общего серверного хранения и мобильного доступа нужна интеграция с проверенной авторизацией OmniHub и его хранилищем на выбранном сервере. Не развёртывать как общедоступный сервис до независимого ревью.

## Реальное MCP-подключение

Адрес: `https://api.pinmetrica.com/pinterest-api/mcp`. Публичное описание сервера на 21.10.2026 объявляет протокол `2024-11-05` и Bearer-авторизацию ключом `pm_…`.

Подтверждённый каталог: `search_keywords`, `suggest_keywords`, `get_categories`, `get_theme`. Сбор пинов, запуск парсинга, мониторинг аккаунтов и статьи не объявлены в этом каталоге. Нельзя считать, что весь веб-интерфейс доступен через MCP.

После предоставления ключа процессу через защищённое окружение:

```bash
node --experimental-strip-types scripts/research/pinmetrica.mjs
node --experimental-strip-types scripts/research/pinmetrica.mjs --query 'Ейск' --project geo-yeisk
```

Первый вызов печатает каталог, второй — канонический JSON для ручного импорта и отдельный список исключённых кандидатов. Обработана только первая страница, до 20 результатов: поле `coverage.complete=false`. Полнота базы не доказана. Дата наблюдения — дата получения ответа, а не дата обновления базы. Страна остаётся неизвестной. Для Makerora EN передавайте `--language en`; язык не определяется автоматически.

В read-only проверке поиска обнаружено совпадение «Ейск» внутри слова «Корейский». Поэтому перед созданием заданий применяется отдельная проверка релевантности. Нулевая выдача после фильтра не означает нулевого спроса.

Пример входа для ручного импорта (значения в этом примере вымышлены и не являются статистикой):

```csv
Ключ;Объём;Тенденция
Жильё в Ейске;12;+2.5%
```

## Прокси: что установлено и чего мы не знаем

В веб-интерфейсе раздел называется «пул прокси для парсинга Pinterest». Доступный клиентский код сборщика передаёт выбор активных прокси и блокирует запуск, если активных нет. Это доказывает требование формы, но не заменяет проверку поведения закрытого сервера.

Показ статуса в кабинете — не гарантия будущего соединения. Срок окончания нужно брать у поставщика прокси. Просмотр наших импортированных данных не зависит от прокси. В схемах четырёх MCP-инструментов пользовательский прокси не передаётся; техническая зависимость обновления данных на стороне сервиса остаётся неизвестной. Отсутствие прокси не проверялось отключением рабочего ресурса.

Для непрерывного текущего парсинга сохраняем действующий прокси. Отказываться от него можно после проверки каждого нужного сценария на альтернативном источнике. Прямой официальный API использует авторизацию и разрешения Pinterest; наличие доступа к публикации не доказывает доступ ко всем методам трендов или ключей.

## Как применять REA

Официальный проект: https://github.com/morluto/rea. Проверенная опубликованная версия для первого исследования: `6.7.0`.

Подготовка подключения Codex без изменения его настроек:

```bash
npx -y rea-agents@6.7.0 setup --client codex --dry-run
```

Для анализа уже полученной с разрешением директории JavaScript:

```bash
bash scripts/research/rea-audit.sh /absolute/target-directory /absolute/new-evidence-directory
```

Скрипт не запускает целевое приложение, не меняет настройки агентов и не отключает проверки REA. В текущей управляемой Linux-среде REA запустился, но `analyze-javascript-application` завершился `capability_unavailable`: системный `ps` не может выполнить проверку владения процессами (`fatal library error, lookup self`). Это незавершённый анализ, а не PASS. Повторять на обычном Mac/Linux с рабочим `ps`; защиту не обходить. Наличие браузера Work не означает наличие локального CDP-порта для REA.

REA помогает исследовать доступные клиентские модули и наблюдаемое поведение. Он не раскрывает закрытую базу и серверный код сервиса. Доказательства, загружаемые клиентские файлы и любые ключи держать вне публичного репозитория. Проверить условия использования данных до массового накопления или распространения.

## До использования в рабочем контуре

1. Независимое ревью изменений и проверка интерфейса в браузере.
2. Серверная авторизация, хранение и секрет MCP в существующем окружении; сохранение данных между устройствами.
3. Реальная идемпотентная передача задания в OmniHub с подтверждением приёма.
4. Доступные официальные источники Pinterest с проверкой разрешений, географии и определения каждой метрики.
5. Проверенный путь сборщика и контроль здоровья прокси; оплаченный срок берётся из кабинета поставщика.

Ни публикация контента, ни prod-развёртывание, ни продление платных услуг этим изменением не выполняются.
