# Закрытый пилот на OnDash

Пилот не меняет DNS, Caddy, Cloudflare, Hermes и рабочий OmniHub. Отдельный Compose-проект слушает только 127.0.0.1. Доступ владельца — через существующее SSH-подключение с туннелем на такой же локальный порт. Это подготовленный вариант; фактический запуск на OnDash не подтверждён.

## Перед запуском

Использовать отдельную копию точного проверенного коммита Pinterest Research Workbench. Не запускать Compose из основной рабочей копии OmniHub или папки с чужим compose-файлом. Сначала сверить commit и отсутствие незапланированных изменений.

`preflight.py` запускается внутри целевой VM с аргументами `--expected-hostname`, `--expected-ip`, `--expected-hostkey-sha256`, `--port`. Значения берутся из подтверждённых данных владельца, а не из текущей машины автоматически. Не использовать `sudo`, отключение SSH-проверок или сброс ключей для прохождения проверки.

Скрипт только читает данные. Docker закреплён за локальным unix:///var/run/docker.sock; DOCKER_HOST/DOCKER_CONTEXT и TLS/API override-переменные не используются. Имя Docker daemon сверяется с именем VM. Допуск требует совпадения имени, IP и публичного ED25519 host key; менее 90% занятого места и не менее 4 GiB доступного места на системном и Docker-разделах; не менее 2 GiB доступной памяти для сборки; доступных Docker/Compose и незанятого порта. Контейнеры, тома и сети ищутся по labels и по точным потенциальным именам, включая ресурсы без labels. Существующие ресурсы проекта `pinterest-research-pilot` требуют отдельной проверки перед продолжением. При недостаточных правах или данных результат — отказ. Результат проверки содержит инфраструктурные сведения; не публиковать его в открытом репозитории.

Успешный preflight не запускает приложение и не подтверждает TLS/аутентификацию. Это проверка условий перед отдельным запуском.

## Запуск

Использовать `compose.research-pilot.yml` и свободный порт из preflight. Передать через защищённое окружение процесса:

- `RESEARCH_PILOT_PORT` — проверенный порт;
- `RESEARCH_OWNER_PASSWORD_HASH` и `RESEARCH_SESSION_SECRET` — настройки владельца;
- `PINMETRICA_API_KEY` — необязателен для проверки импорта; без него MCP закрыт.

Секреты не включать в командную строку, файлы проекта, git или журналы. Не запускать `docker compose config` без `--quiet`, потому что полный вывод раскрывает значения окружения.

Команды ниже явно задают локальный Docker endpoint, фиксированное имя проекта и отключают чтение .env. Это исключает влияние унаследованных DOCKER_CONTEXT, DOCKER_HOST, COMPOSE_PROJECT_NAME и COMPOSE_ENV_FILES. Не сокращать команды и не запускать их через другой Docker context. После настройки окружения команда запуска:

```bash
env -u DOCKER_HOST -u DOCKER_CONTEXT -u DOCKER_TLS_VERIFY -u DOCKER_CERT_PATH -u DOCKER_API_VERSION docker --host unix:///var/run/docker.sock compose --env-file /dev/null -p pinterest-research-pilot -f compose.research-pilot.yml up -d --build
```

Контейнер работает от uid 1001, порт внутри 3000; SQLite находится в отдельном именованном томе. Запоминание настроек Docker позволяет пережить перезапуск контейнера. `RESEARCH_SECURE_COOKIES=false` допустим здесь только потому, что HTTP остаётся на loopback и проходит через SSH-туннель. Внешний порт и домен этой конфигурацией не создаются.

## Приёмка и остановка

Проверить на реальном сервере: loopback-привязку порта, недоступность порта снаружи, вход/выход, сохранность данных после пересоздания контейнера и восстановление копии. Отдельно проверить интерфейс с компьютера и телефона перед более широким доступом.

Остановить только этот проект, сохранив том:

```bash
env -u DOCKER_HOST -u DOCKER_CONTEXT -u DOCKER_TLS_VERIFY -u DOCKER_CERT_PATH -u DOCKER_API_VERSION docker --host unix:///var/run/docker.sock compose --env-file /dev/null -p pinterest-research-pilot -f compose.research-pilot.yml down
```

Не добавлять `--volumes`: это удалит данные. Открытый HTTPS-вход требует отдельной проверенной защиты от перебора; закрытый пилот не заменяет эту проверку.
